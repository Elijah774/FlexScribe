1. PROJECT SUMMARY
================================================================================

FlexScribe is a personal finance management web application targeting South
African university students and young professionals. It allows users to:
- Track and manage recurring subscriptions (Netflix, Spotify, etc.)
- Maintain a virtual wallet with deposit/withdrawal/transfer capabilities
- Set and track financial savings goals
- Manage dependants (family members) with allowance allocation
- Upload bank statements for AI-powered spending analysis
- Generate compiled financial reports (downloadable as CSV)
- View analytics dashboards with spending trends and category breakdowns
- Earn a "ScribeScore" (financial health metric) that improves with usage

TECH STACK:
- Frontend: Vanilla HTML/CSS/JavaScript (no frameworks). SPA architecture
  using a single MASTER.html shell with dynamically loaded page panels.
  Chosen for simplicity, no build step, and direct file:// compatibility.
- Backend: Node.js with Express.js (server/ directory, port 3000).
  Chosen for JavaScript full-stack consistency and npm ecosystem.
- Database: Microsoft SQL Server (FlexScribeDB). Chosen because it is the
  prescribed DBMS for the university module (WRRV).
- Auth: JWT (jsonwebtoken) with bcryptjs password hashing.
- File parsing: pdf-parse (PDFs), xlsx (Excel), native CSV parsing.

------------------------------------------------------------------------
4.1 AUTHENTICATION
------------------------------------------------------------------------
What: Email/password registration and login with JWT token-based sessions.
New users get 500 ScribeScore, a virtual wallet with generated card number,
and a MainMember record.

Algorithm:
- Passwords hashed with bcryptjs (cost factor 10).
- JWT contains { subscriberID, email, userType }, expires in 7 days.
- Token stored in sessionStorage (cleared on tab close).
- Every API call includes Authorization: Bearer {token} header.
- Auth middleware (authenticateToken) verifies token on all /api/* routes
  except /api/auth/login, /api/auth/register, /api/health.

Files:
- Frontend: pages/login.html, scripts/login.js, scripts/api.js (Auth namespace)
- Backend: server/routes/auth.js, server/middleware/auth.js
- Database: Subscriber table (passwordHash column)

Key functions:
- scripts/login.js: login form submit handler (line 134)
- scripts/api.js: Auth.login(), Auth.register(), Auth.getUser()
- server/routes/auth.js: router.post('/register'), router.post('/login')
- server/middleware/auth.js: authenticateToken(), generateToken()

Limitations:
- No email verification on registration.
- No password reset endpoint (forgot-password is UI-only, no email sent).
- No refresh token mechanism — after 7 days, user must re-login.
- No rate limiting on login attempts.

4.2 SUBSCRIPTIONS
------------------------------------------------------------------------
What: Full CRUD for recurring subscriptions. Users add services with name,
amount, billing cycle, category, date. Can pause/unpause, edit, delete.
Category-based donut chart and upcoming payments list.

Algorithm:
- Monthly cost normalisation: weekly*4.33, quarterly/3, yearly/12.
- Upcoming payments = active subs with nextPaymentDate within 30 days.
- Donut chart computed from category groupings of active subscriptions.
- Validation: name required, amount > 0, billing date required and cannot
  be in the past.
- Provider recommendations: PROVIDERS array in backend/subscriptions.js
  with 14 SA-relevant services. Excludes already-subscribed services.

Files:

- Backend: server/routes/subscriptions.js

4.3 VIRTUAL WALLET

transfer to goals, send to dependants. All operations create WalletTransaction

- Card displayed masked: first 4 + dots + last 4 (dashboard), dots + last 4 (wallet).

4.8 BANK STATEMENT UPLOAD & PARSING
------------------------------------------------------------------------
What: Users upload PDF, CSV, or XLSX bank statements. Server parses
transactions, analyzes income/expenses/net, detects subscriptions, stores
results, and awards +100 ScribeScore.

Algorithm (CSV parser):
- Scans first 5 rows for header keywords (date, description, amount, etc.)
- Auto-detects column positions by name (supports any column order).
- Handles separate debit/credit columns (FNB, Standard Bank format).
- Respects quoted CSV fields.

Algorithm (PDF parser):
- Extracts text via pdf-parse library.
- Tries 5 date patterns: YYYY-MM-DD, DD/MM/YYYY, DD/MM/YY, DD Mon YYYY, DD Mon YY.
- Tries 3 amount patterns: R1,234.56, European 1.234,56, spaced 1 234.56.
- Takes last amount on each line (skips balance column).
- Fallback mode: if strict parsing fails, scans for R + digits on any line
  and associates with the most recent date seen.

Algorithm (XLSX parser):
- Reads first sheet, scans first 10 rows for header row.
- Detects columns by name (date, description, amount, debit, credit).
- Handles separate debit/credit columns.

Algorithm (Subscription detection):
- Matches transaction descriptions against 60+ known service names
  (Netflix, Spotify, DSTV, Vodacom, Discovery, etc.).
- Finds recurring patterns: same merchant 2+ times with amounts within
  10% of each other.
- Returns confidence: 'high' (known service or 3+ occurrences) or 'medium'.

Files:
- Frontend: scripts/reports-ui.js (_uploadFile, _bindUpload),
            scripts/reports.page.js (upload zone HTML),
            scripts/api.js (BankStatements.upload)
- Backend: server/routes/bank-statements.js
- Database: BankStatement, ScribeScore tables

Key functions:
- bank-statements.js: _parseCSV(), _parsePDF(), _parseXLSX(),
  _detectSubscriptions(), _analyze(), router.post('/upload'),
  router.get('/report')
- reports-ui.js: _uploadFile(), _resetUploadZone()
- api.js: BankStatements.upload(file), BankStatements.getReport()

Limitations:
- PDF parsing is regex-based and fragile for complex bank layouts.
- No OCR for scanned/image PDFs (only text-based PDFs work).
- XLSX parsing requires the 'xlsx' npm package to be installed.

4.9 REPORT GENERATION & CSV EXPORT
------------------------------------------------------------------------
What: Compiles a financial report from wallet transactions, subscription

7. HOW TO RUN THE PROJECT
================================================================================

PREREQUISITES:
- Node.js v18+ (tested on v24.19.0)
- SQL Server (local instance, Windows or SQL auth)
- npm (comes with Node.js)

STEP 1: Clone the repository
  git clone https://github.com/ivyClique3/FlexScribe.git
  cd FlexScribe

STEP 2: Create the database
  Open SQL Server Management Studio (SSMS).
  Run: flexscribe-local-database.sql
  This creates FlexScribeDB and all tables with seed data for SubscriptionCategory.

STEP 3: Run the migration (if not already done)
  In SSMS, run: migrations/001-add-cardNumber.sql
  This adds the cardNumber column to VirtualWallet.

STEP 4: Configure environment variables
  Create file: server/.env
  Contents:
    DB_SERVER=localhost
    DB_NAME=FlexScribeDB
    DB_USER=your_sql_username
    DB_PASSWORD=your_sql_password
    DB_TRUSTED=false
    PORT=3000
    JWT_SECRET=your_secret_key_here

  If using Windows Authentication, set DB_TRUSTED=true and omit
  DB_USER/DB_PASSWORD.

STEP 5: Install dependencies
  cd server
  npm install

STEP 6: Start the server
  npm start
  (or: node server.js)

  You should see:
    Connected to SQL Server: FlexScribeDB
    FlexScribe API running on http://localhost:3000

STEP 7: Open the app
  Browser: http://localhost:3000/landing.html (landing page)
  Or: http://localhost:3000/pages/MASTER.html (app directly)
  Or: http://localhost:3000/pages/login.html (login page)

COMMON ERRORS:
- EADDRINUSE: Port 3000 already in use. Kill the existing node process:
  netstat -ano | findstr :3000  → note the PID
  taskkill /PID <pid> /F
  Then restart.

- Cannot find module 'multer' / 'pdf-parse' / 'xlsx':
  Run: cd server && npm install

- Login ConnectionError / ETIMEOUT:
  SQL Server is not running. Start it via SQL Server Configuration Manager.
  Or check your .env credentials.

- "Invalid column name 'cardNumber'":
  Run migrations/001-add-cardNumber.sql in SSMS.

- "Cannot insert the value NULL into column 'twoFactorEnabled'":
  The Subscriber table has NOT NULL columns added after the initial schema.
  Check that all INSERT statements include: twoFactorEnabled, theme,
  notifyPayments, notifyGoals, notifyWeekly, createdAt, updatedAt.

9. KNOWN ISSUES / NOT YET DONE
================================================================================

INCOMPLETE:
1. cardNumber column migration (migrations/001-add-cardNumber.sql) must be
   run manually in SSMS — the MCP connection lacks ALTER permissions.
   Until run, card number displays as "---- ---- ---- ----" placeholders.

2. scripts/analytics-ui.js still contains inline ANALYTICS_DATA seed
   (lines 10-90). This renders hardcoded values if the API is unavailable.
   Should be replaced with empty-state + API fetch similar to reports.

3. Dashboard ScribeScore rings (dashboard.page.js) start at 0 but are NOT
   dynamically updated from the ScribeScore API. They only change if the
   HTML is manually edited or a JS function is added to update stroke-dashoffset.

4. VirtualWallet.pendingIn and pendingOut are never written to by any
   endpoint — they always stay at 0/default values.

5. PaymentSchedule table is never automatically populated when subscriptions
   are created or billing dates pass.

6. Notifications are never auto-generated by the system (no triggers on
   subscription payments, goal milestones, etc.).

FRAGILE:
7. PDF bank statement parsing (server/routes/bank-statements.js _parsePDF):
   Complex bank statement PDFs may not extract correctly. Only text-based
   PDFs work — scanned/image PDFs will return 0 transactions.

8. The frontend has two "backend" layers: the backend/*.js localStorage
   stores AND the server/routes/ API. Some UI components call the store
   which then calls the API. If the API is down, the store returns stale
   localStorage data without clear indication to the user.

9. flexscribe-backend/ (Java Spring Boot) requires Java 21 and Maven, which
   are not installed on the development machine. It cannot be built or run
   without environment changes. The Node.js server/ is the active backend.

KNOWN BUGS:
10. The "Trends Over Time" section on the Reports page shows "No trend data
    yet" permanently — there's no endpoint call to populate it (the analytics
    trend endpoint exists but reports-ui.js _loadPageData doesn't call it).

11. The Register endpoint in server/routes/auth.js may fail if the Subscriber
    table has columns without defaults that were added after the original
    schema (e.g., dateOfBirth can be NULL so it's fine, but if new NOT NULL
    columns are added without updating the INSERT, registration will break).

12. After generating a report, the "Generated Reports Table" only updates
    on the next page load (no immediate re-render after compile).

13. Role-based access control (tier system in layout.js) is commented out
    for development — all pages are accessible to all users regardless of
    plan type.
